# Windows releases are one signed installer, and the update runs it

The owner saw the nine loose files of a 0.2.x release (the program, four ffmpeg libraries, license texts) and called the release page "super messy": a release should be the installer (2026-11-25). From 0.3.0 a Windows release carries one Windows file, `eyepiece-<version>-windows-setup.exe`, beside the release manifest. It is made with Inno Setup from `scripts\installer.iss`: for the user alone, with no admin prompt, into `%LOCALAPPDATA%\Programs\eyepiece`, with a Start menu entry and an uninstaller in Settings > Apps, and signed, with its uninstaller, by the same Artifact Signing as the program. The update runs that installer in place of ADR 0007's own in-place update (each changed file renamed aside, the new one copied in, a rollback, and a tidy of the set-aside files at the next start), which is gone.

Why one installer and not a zip or the loose files: one file to download by hand, and one way a build reaches a machine, by hand or by update. Inno already does what the in-place update did itself: it replaces files a closing program held, puts everything back when an install fails, and registers an uninstaller.

## Consequences

- The manifest's form is unchanged: the installer is its one `file =` line, with its size and SHA-256. The player takes a release only when the manifest names `eyepiece-<that version>-windows-setup.exe`, and takes no other file, so a manifest cannot have it run another program.
- The installer gets ADR 0007's checks: its size and SHA-256 as it lands and again from the disk, then a signature Windows trusts from the running program's signer. A build that is not signed itself still never updates itself. From its check until it starts, the player holds the installer open for reading only, so nothing can change it in between.
- Then the player starts it with `/SILENT /NORESTART /update=<its pid>` and closes. The installer waits for that process to end (up to 30 s; after that, Windows' Restart Manager closes a player still holding the files, as a silent install does, which was seen in a scratch install on 2026-11-25), installs, and starts the new build. The files open in the player go with it as `EYEPIECE_REOPEN`, a command line the player quotes and the installer hands on. `/SILENT` shows the install's progress, and any error in Inno's own message. Inno rolls a failed install back and then starts nothing, so the player stays closed (Inno's documented behavior, not tried here).
- Every update downloads the whole installer, where 0007 fetched only the files that changed: 40.6 MB for a signed 0.3.0 build on 2026-11-25, almost all of it ffmpeg's libraries.
- The update installs where the installer does, not where the player runs: the folder of an earlier install, else `%LOCALAPPDATA%\Programs\eyepiece`. A signed build run from another folder is updated into that one.
- Old 0.2.x installs have no path to 0.3.0 and need none: the repo is private, so none of them reaches a release (they show "could not check"). They also read a manifest only when it names `eyepiece.exe`, which 0.3.0's does not, so 0.3.0 is installed on them by hand.
- A macOS disk image can be a release asset too (`scripts\release.ps1 -Mac`), uploaded as it is and kept out of the manifest.
